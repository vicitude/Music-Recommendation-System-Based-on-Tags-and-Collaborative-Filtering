# B1 批量音乐导入使用说明

## 如何操作
1. 保持本机 MySQL 和后端启动；若后端未自动重载，请重启原后端启动窗口。不需要执行数据库迁移。
2. 打开 `http://127.0.0.1:8000/admin/music/song/batch-import/`，使用管理员登录。也可在歌曲列表点击“扫描目录并批量导入”。前端代理运行时可使用5173端口同路径。
3. 将有权使用的音乐放在 `D:\AAA素材库\song`，点击“扫描本地素材目录”。支持子目录，扫描不修改音频或创建歌曲。
4. 查看批次汇总和异常原因。资料完整项可以一次处理，不需逐首打开编辑页。
5. 确定要执行时，勾选“确认创建草稿并复制音频”，点击“批量导入 / 重试失败项”。已有指纹跳过，不覆盖既有歌曲。
6. 页面显示逐首成功、跳过或失败。保存批次页面网址可以再次打开或重试；批次仅限创建它的管理员查看。

## 当前边界
- MP3/WAV/OGG，每首30MiB，每批500首；超限需分目录。服务端可通过 Django 设置 `LOCAL_IMPORT_SOURCE_ROOT` 指定其他目录，不在页面接受任意磁盘路径。
- 默认只创建下架草稿，复制到项目媒体目录，不自动发布，不为歌曲伪造标签、歌手或许可。现有发布按钮不变；批量发布在B3处理。
- 本阶段提取基础资料、时长和封面是否检出，不保存封面图片。MP3支持ID3v2.3/v2.4/v1和Layer III；其他编码/格式不强行转换。完整解码与试听仍需实际播放验收。
- B2基础候选已接入，使用及缺解码器边界见 `docs/B2-自动标签候选使用说明.md`；没有充分依据时允许标签为空。
- 报告包含本地路径、批次归属和结果，存于私有 `local-import-batches/`，已加入Git忽略。不要手动放到媒体目录或上传仓库。
- 一首失败不影响其他成功项。数据库保存失败可能留下未关联的媒体副本，报告会记录；不自动删除。数据库与文件系统不保证崩溃时跨系统原子性。
