## 4. 最近播放接口契约

### 请求与响应

`GET /api/v1/me/history/?page=N`。身份来自当前认证会话，不接受通过用户ID选择历史所属人。页号从1开始，省略时为第1页，`page_size` 固定20，不能由客户端扩大。

成功响应包含 `items`、`total`、`page`、`page_size`；每条 items 为 `{song: 完整Song, last_played_at: 日期时间字符串}`。`total` 是过滤后按歌曲去重的总数，不是行为条数。日期时间复用既有 API 格式，前台按时区解析展示。空响应示例：

```json
{"items": [], "total": 0, "page": 1, "page_size": 20}
```

### 聚合与排序

1. 仅当前用户已被服务器接受并记录的 PLAY 参与，COMPLETE、SKIP、收藏、评分均不参与。最近播放不表示已经听完；点击播放但未被服务器接受的事件不能作为历史依据。
2. history 接口只读，不新增行为数据；重复播放只更新同歌曲聚合后的最新时间，不按重复次数堆叠条目。
3. 按歌曲取 PLAY 的最大 `occurred_at` 作为 `last_played_at`，不是行为写入时间，也不能混入他人时间。
4. 复用现有歌曲可见性过滤；下架、隐藏等不可见歌曲不出现在 items 或 total，不返回空歌曲占位。
5. 先过滤、聚合，再计算总数和分页，不能先分页行为再去重。
6. 最新时间降序，时间相同按歌曲ID升序；数据不变时顺序稳定。

### Song、路径和错误

`song` 复用既有完整对外 Song，而非仅返回ID或标题。现有字段包括 `id`、`title`、`artist`、`album`、`duration_ms`、`tags`、`playable`、`stream_url`、`attribution_text`、`source_url`、`license_name`、`license_url`、`current_rating`；评分属于当前用户，标签与其余字段保持既有语义。

不得返回 `file_path`、服务器绝对路径、本地音频目录或内部文件定位信息。`stream_url` 仅为既有受控播放接口地址或 null，不能替换成音频磁盘路径。可见不等于可播放，不能绕过既有 playable 和播放接口检查。

未认证、非法页号及越界页复用既有认证、分页与错误响应约定，不另造错误码或状态码；具体边界响应待实施测试汇总。前台错误时不展示上一账号数据。
