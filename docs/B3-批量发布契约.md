# B3 批量发布

## v68 同页直接发布（取代强制分两步）
用户明确要求简化：批次页的主流程为扫描→打标签→一键导入并发布。明确确认采用模型候选后，新歌创建、标签写入和发布检查置于同一事务；失败不留下正式歌曲，可能保留未关联媒体副本并记录，不擅自删除。既有歌曲不覆盖、不自动发布，已有草稿可走批量发布页。只保存草稿作为折叠可选项，不再强制。

私有批次本来已写磁盘，重启不主动删除；页面新增按账号隔离的最近10个批次链接，可恢复分析结果。发布列表为空仅说明没有active=False的歌曲，不能推断批次丢失。未读取真实MySQL，不宣称本机具体草稿数量或丢失原因已核验。

授权：用户要求补齐批量发布入口。范围为已有歌曲草稿发布，不重新分析、导入或覆盖标签，不自动下架。歌曲列表与导入页提供明显链接。

独立页面默认显示未发布歌曲，支持逐首勾选和全选；POST需CSRF、change_song权限和明确确认。每首复用单曲发布表单校验音频、MIME、时长和必填资料；曲风1—2、情绪1—3、场景1—2且每类至少一个启用标签。合格项独立事务发布并记录管理员日志；不合格项保留原状态并逐首显示原因，已发布项跳过。重复提交不刷新已发布歌曲的发布时间。发布不代表人工试听或标签准确性证明。

验证要求：混合成功/失败、重复、缺失/超限/停用标签、文件异常、权限、CSRF、确认和页面入口；不代用户操作真实库。
