## 使用步骤
1. 重启本机后端，刷新并登录后台。打开 http://127.0.0.1:5173/admin/music/song/batch-import/ 。
2. 点击“扫描本地素材目录”，仍扫描服务端已配置目录，默认D:/AAA素材库/song。支持MP3/WAV/OGG，结构错误或资料缺失需按页面提示处理，不绕过扫描门槛。
3. 在“三类标签分析与批量预览”中选择1—5首，点“分析三类标签（1至5首）”。页面需等待模型，完成后返回当前批次。可分组重复分析，历史已分析结果保留。
4. 查看曲风、情绪、场景三列。★低把握补位不是可靠识别结论；场景是情绪规则推导的使用建议，不是客观音频属性。成功标签数量为1—2 / 1—3 / 1—2，损坏、非音乐竞争或质量失败不强补。
5. 勾选“确认创建草稿并复制音频”及“确认采用下方多标签候选（含低把握补位和场景建议）”，点击“批量导入 / 重试失败项”。无需逐首确认，但将处理整批可导入歌曲；如果只分析了部分歌曲，其余未分析项会单独失败，已成功项保留，继续分析后可重试。
6. 已有指纹歌曲始终跳过，不覆盖手改标签，扫描现有40首不会重新替换标签。新草稿保持下架；在执行结果点“查看草稿 / 修改标签”进入现有编辑器，可增删改后保存发布。

不勾选多标签确认时仍允许只导入资料草稿，标签可以未完成。旧规则兼容折叠区保留，不能与多标签确认同时勾选，避免同一歌曲混入两套标签。

## 数量与发布
编辑上限已同步曲风2、情绪3、场景2；发布时每类至少一个启用标签。未完成可以普通保存草稿，不强迫在第一次资料录入时随便填标签。已发布旧歌原位编辑仍可维护，点击发布会校验三类。音频检查及原发布按钮不变。

## 证据与权限
模型使用独立Python与固定本地权重，Django不加载torch；独立worker调用180秒限时，最多5首。后端检查模型/策略版本、原始分数、实际取样范围，并重新执行候选判断，对篡改、过期或失败结果不写标签。源文件分析前后/导入前指纹复核保持。批次归属、CSRF、add_song/change_song以及写标签add_tag/add_songtag权限保持。停用标签不自动复活。

写入仅本次新建草稿，每首事务隔离，失败继续列明。候选来源/等级/补位依据与实际采用清单保留在私有批次JSON的minimum_analysis/applied_tags中，不写到公开媒体目录，也不伪装为SongTag已有置信度字段。模型推理不自动写正式标签，只有用户显式确认保存才会写入。
