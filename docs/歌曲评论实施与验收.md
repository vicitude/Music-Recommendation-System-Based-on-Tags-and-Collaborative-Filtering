## 模型契约
- Comment映射music_comment，含自动主键id、必填user/song外键、content、created_at；两外键均为PROTECT，有评论引用时不得级联删除用户、歌曲或评论。
- content必须为字符串，trim后保存并校验1—500字符；缺失、null、非字符串、纯空白及超过500字符均拒绝，不自动截断。
- created_at由服务端创建时记录；作者取当前登录用户，歌曲取路径，不接受客户端指定作者、歌曲归属或时间。
- 原契约以0003_recommendation_scene为迁移末项；作者最终报告0004_comment仅新增music_comment、双外键PROTECT，makemigrations检查无漂移。真实迁移未执行，部署前仍须核对目标迁移链，不覆盖既有迁移。

## API契约
路径沿用现有API前缀。统一评论项：

```json
{"id":1,"song_id":7,"author":{"id":2,"username":"listener"},"content":"很好听","created_at":"2026-11-11T08:00:00Z","can_delete":false}
```

| 请求 | 条件 | 成功响应 |
|---|---|---|
| GET songs/<id>/comments/?page=N | 公开，仅active=True歌曲；默认第1页，固定每页20条，created_at/id双字段倒序 | 200，{items:[评论项],total,page,page_size}，page_size=20 |
| POST songs/<id>/comments/ | 活跃登录用户、有效CSRF、已上架歌曲；JSON {content} | 201，直接返回评论项 |
| DELETE comments/<id>/ | 活跃登录用户、有效CSRF、本人评论且歌曲仍上架 | 204，无响应正文 |

- author仅返回id和username，不暴露邮箱等私密信息；can_delete按当前身份计算，访客及非作者为false，本人为true。前端标记不能替代服务端鉴权；管理员不能通过公共DELETE接口删除他人评论。
- 歌曲不存在或下架时GET/POST为404；DELETE对别人评论、重复删除、不存在或下架歌曲评论均为404，不泄露目标详情。
- 内容不合法返回400；未登录、账号非活跃或CSRF失败拒绝写入，沿用现有认证及错误响应规则，不修改全局认证机制。
- 非法或越界分页沿用现有歌曲列表分页口径并补对应测试；客户端不能改变固定20条限制。

## 后台与前端
- 后台支持查询、搜索、筛选和受权限保护的删除；禁止新增评论、修改原文或作者，直接提交也不得绕过。
- 歌曲详情评论组件提供发表、分页、本人评论二步确认删除，以及空、错误、加载状态；取消删除不发请求。等待期间防重复操作，服务端成功后才更新显示，失败可重试、不假报成功；末页删空后回到有效页。
- 评论按纯文本显示，禁止v-html及其他HTML执行渲染；HTML输入只作文字展示。
- 换歌、换号、换页和卸载时使旧请求失效；迟到的列表、发表、删除响应不得覆盖新上下文，也不得留下旧账号的删除权限、输入内容或提示。
- 不含回复、编辑、点赞；不采集推荐行为，不生成播放/收藏/评分记录，不改变推荐算法或排序。
