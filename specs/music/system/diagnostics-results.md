# 管理员推荐诊断页

日期：2026-11-02。用户批准先实现管理员诊断，不包含模拟账号写入或正式评价实验。

## 使用

重启原后端后打开 http://127.0.0.1:5173/admin/music/user/recommendation-diagnostics/ ，用music_admin登录，选择需要分析的普通用户账号，点击“查看当前试算”。后台首页及用户列表也有入口。

页面显示兴趣标签、正反馈去重歌曲数、同源其他活跃账号数、目标/实际融合权重、信号退化说明，以及最多10首的歌曲名称、标签分、协同分、融合分、来源、贡献邻居数、解释与标签证据。分数是归一化分而不是概率；无协同信号正常退化，不能据此声称协同效果已验证。相似用户至少有2首共同正反馈。

当前试算复用既有load_inputs/recommend，不写快照、不改变行为、兴趣、歌曲或限流。另列最新已保存快照的日期、版本和条数，并非历史回放；两者因时间、收藏、数据变化可能不同。每首贡献邻居数不等于页面其他账号总数。

## 安全与验证

仅活跃staff且同时具有view_user/view_song可GET；其他方法405，非法账号400，数据库/算法错误503脱敏。无新公开API/迁移/依赖，不读取密码或浏览器凭据。页面private/no-store并继承Django管理后台禁缓存。

8项专项、292项全量后端内存测试通过，文档门禁及4项自测通过，无模型漂移。覆盖初始不计算、权限/参数/方法、只读快照、热门/标签/混合、同源隔离、分数与原引擎一致、异常脱敏。使用内存SQLite及模拟文件存在性，不是MySQL/浏览器验收。未代操作真实账号、创建模拟行为或改变用户推荐；需用户重启后在实际页面确认。

用户已反馈40首发布且兴趣、曲库、播放、收藏歌单、每日推荐5项流程正常；此为用户反馈，不冒充Agent实机验收。推荐质量、正式对比实验及论文结果仍待开展。
