# 从模拟数据切换到真实内测数据

## 切换原则

模拟数据用于开发和演示链路；真实内测数据用于正式实验。两者不混合、不覆盖、不共用结果目录。真实数据没有收集完成前，保持 `SIMULATED` 状态，不修改为 `REAL`。

## 真实数据最低字段

### 歌曲

- 稳定的 `song_id`
- 可核对的歌名、歌手和标签 ID
- 标签类型至少区分风格、情绪、场景
- 研究使用范围和来源/许可证据

### 用户

- 匿名化的稳定 `user_id`
- 明确的兴趣标签来源：主动选择或行为推断
- 不写入密码、Cookie、Token、手机号等敏感信息

### 行为

- `user_id`、`song_id`
- 行为类型或正负反馈映射
- 带时区的真实 `occurred_at`
- 可追溯的事件来源和去重规则

## 切换步骤

1. 复制数据模板，建立独立的真实研究目录，不覆盖模拟目录。
2. 核对歌曲、标签、用户和行为的字段映射与去重规则。
3. 补齐来源、许可、时间范围和匿名化说明。
4. 将 manifest 的 `origin` 设置为 `REAL`，并确认 `timestamps_are_real=true`。
5. 运行评价命令生成独立报告，检查时间切分和目标用户数量。
6. 只把真实报告用于论文实验表格；模拟报告仍保留为程序自检证据。
7. 对真实前台业务按 `live-acceptance.md` 逐项验收，并单独记录失败原因。

## 禁止事项

- 不用随机时间戳冒充真实行为时间。
- 不将本地下载路径或“仅学习使用”写成许可证明。
- 不把线上演示库行为直接当成研究实验数据。
- 不把模拟指标与真实指标合并平均。
- 不修改现有用户未提交文件来隐藏数据缺口。
