# 模拟业务联调与阶段 9 验收包

## 1. 目的与边界

本文件用于在真实用户内测数据尚未收集前，先验证系统各模块之间的业务连接关系。它使用内存测试库、固定模拟数据和前端自动化断言，不连接用户项目专用 MySQL，不读取真实密码，不把模拟结果写成真实用户效果。

阶段 9 的当前结论只能回答：页面、接口、推荐链路和数据字段是否能够按约定协作。它不能回答真实 MySQL 兼容性、真实音频播放质量、用户满意度或推荐效果是否提升。

## 2. 模拟验收范围

| 编号 | 链路 | 模拟通过条件 |
|---|---|---|
| SIM-01 | 注册与登录 | 注册输入校验、登录路由和失效会话处理符合前端契约 |
| SIM-02 | 兴趣冷启动 | 选择 3—5 个标签并持久化；无行为用户不冒充协同个性化 |
| SIM-03 | 曲库浏览 | 搜索、标签筛选、分页连续编号和歌曲详情请求参数一致 |
| SIM-04 | 收藏与评分 | 收藏爱心原位切换；评分 1—5 分写入并更新当前值 |
| SIM-05 | 歌单 | 创建歌单取得服务端 ID 后再进入详情；成员增删使用正确请求 |
| SIM-06 | 播放行为 | 单播放器、队列切换、暂停/拖动边界和四种播放模式符合状态机 |
| SIM-07 | 推荐融合 | 内容、User-CF、Item-CF 缺路时有安全回退；解释只引用真实证据字段 |
| SIM-08 | 场景权重 | 主动场景和时段默认值进入推荐上下文，诊断展示实际权重 |
| SIM-09 | 实验看板 | 模拟报告明确标记 `SIMULATED_SELF_TEST`，页面可展示和导出 |
| SIM-10 | 管理员诊断 | 只读诊断不修改每日快照、行为或收藏数据 |

## 3. 当前证据

- 后端推荐、行为、评分、诊断和评价专项测试使用 `config.test_settings` 的内存 SQLite。
- 前端测试覆盖接口客户端、页面交互、收藏、评分、播放器和四种播放模式。
- 实验看板使用固定 seed 42 的模拟摘要，页面和导出文件均标注模拟状态。
- `verify_spec.py --self-test --check-environment` 只检查文档与环境，不替代业务验收。

## 4. 不可从模拟验收推出的结论

- 不能推出 MySQL 9.2 专用库已完成本轮全部业务验收。
- 不能推出本地音频在用户浏览器中可以稳定解码或播放。
- 不能推出三路融合真实效果优于任一基线。
- 不能推出真实冷启动用户的 Recall、满意度或留存得到提升。
- 不能把模拟用户、模拟歌曲和模拟行为写入正式实验结果。

## 5. 真实内测切换前置条件

真实数据到位后，先创建独立研究数据目录和 `manifest.json`，声明来源、许可依据、`origin=REAL`、字段映射、时区和真实时间戳。然后使用 `evaluation-runbook.md` 的时间切分规则运行评价命令，并将结果与当前模拟报告分开保存。

真实业务验收仍需由项目所有者在本机完成：启动后端、登录前台、播放有权使用的音频，按 `live-acceptance.md` 逐项记录数据库、浏览器、音频和权限结果。代理不得用内存测试替代这些操作。
